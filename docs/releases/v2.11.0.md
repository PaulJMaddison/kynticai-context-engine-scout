# KynticAI Scout v2.11.0

KynticAI Scout v2.11.0 is a major open-core boundary and runtime-hardening release. It makes Scout's role explicit as the inference-free **Explore** product, moves sales-specific intelligence into a reference consumer, strengthens production readiness and source-event correctness, and aligns the APIs, UI, documentation, and packaging around the current KynticAI product architecture.

## Highlights

- **Clean product boundary**: Scout is **Explore**, Fortress is **Prove**, and Elite is **Scale**. Cloud/control-plane capabilities are supporting infrastructure rather than a separate product.
- **Inference-free core**: sales-specific relationship weighting, next-action heuristics, prompt envelopes, and reference-agent behaviour now live in the `KynticAI.Scout.Reference.Sales` example package rather than the production Scout runtime.
- **Reference-only next action**: the canonical `/api/v1/intelligence/next-action` surface fails closed with `501 feature.external_consumer_required` unless an external/reference implementation is deliberately wired.
- **Cross-instance source-event idempotency**: PostgreSQL ingestion uses a transaction-scoped advisory lock keyed by tenant, source system, and event ID before the authoritative duplicate/conflict check.
- **Persistent key proof**: Data Protection restart tests prove encrypted connector secrets survive a provider restart with the same key ring and fail closed when the key ring changes.
- **Production shape**: self-hosted and managed-data-plane modes require production-safe configuration; fictional CustomerOps data and demo fallbacks are blocked from production shape.
- **Tenant boundary clarity**: tenant remains the security boundary. Workspaces are organisational and are not represented as a complete hard-isolation boundary.
- **API compatibility**: `/api/v1` is canonical machine REST. `/api/rest` remains available only as explicitly deprecated compatibility routing.
- **Production UI discipline**: LocalDemo/reference sales navigation is hidden when production demo fallback is disabled.
- **SQL connector hardening**: connector mode is explicit, and the fictional CustomerOps database path is documented and enforced as LocalDemo/reference-only.
