# KynticAI Scout v2.10.0

KynticAI Scout v2.10.0 is a hardening and correctness release. It removes a
synchronous database call from API client key management, aligns the legacy
REST authorisation semantics with the v1 and GraphQL surfaces, makes expiry
computation deterministic through the injected time provider, and closes a
low-severity information disclosure on `/api/platform/config` in hosted
deployments.

## Highlights

- API client key create/rotate/revoke now run fully asynchronously end to end
  (`EnsureWorkspaceAccessAsync`), removing the blocking `SaveChanges` call.
- Cross-tenant requests on the legacy `/api/rest/*` endpoints now return `403
  authorization.denied`, matching v1 and GraphQL behaviour.
- The `/api/auth/token` endpoint and the permission-denied audit middleware now
  use the injected `TimeProvider`, making expiry and audit timestamps
  deterministic.
- `/api/platform/config` now requires authorisation in hosted (SaaS) mode; it
  stays anonymous for local development. Nothing in the SDK or web app consumes
  it, so no consumer change is required.
- Confirmed the public connector catalogue endpoint is anonymous by design: the
  web app loads it without a bearer token.

## Verification

- .NET Release build (warnings as errors) passes with no warnings.
- Backend unit tests (112) and SDK tests (40) pass.
- Integration and end-to-end suites were not run as part of this release's
  local verification (live/external dependencies are opt-in per repo policy);
  the existing cross-tenant integration tests already assert the new `403`
  behaviour.
